# Use Case — процесс «Оформление заказа»

## UC-01. Отменить заказ

- **Актёр:** Менеджер
- **Цель:** Отменить заказ клиента и зафиксировать причину отмены
- **Предусловия:** Заказ существует в системе и имеет статус, отличный от «Отправлен»

**Основной поток:**
1. Менеджер открывает карточку заказа
2. Система отображает текущий статус заказа и доступные действия
3. Менеджер нажимает «Отменить заказ»
4. Система запрашивает причину отмены
5. Менеджер указывает причину
6. Система меняет статус заказа на «Отменён»
7. Система сохраняет причину отмены в истории заказа

**Альтернативные потоки:**
- Если заказ имеет статус «В сборке» — после шага 6 система дополнительно уведомляет кладовщика об отмене (продолжение с шага 7)

**Исключения:**
- Если заказ уже имеет статус «Отправлен» — кнопка «Отменить» недоступна, сценарий не может быть начат

**Постусловия:** Заказ имеет статус «Отменён», причина отмены сохранена, при необходимости кладовщик уведомлён

## UC-02. Добавить товары к заказу (проверка наличия)

- **Актёр:** Менеджер
- **Цель:** Добавить товары к заказу с проверкой наличия на складе
- **Предусловия:** Заказ создан в системе, позиции ещё не добавлены

**Основной поток:**
1. Менеджер открывает систему с остатками на складе
2. Система отображает название, цену и остаток по каждому товару
3. Менеджер добавляет товар к заказу с указанием нужного количества
4. Система сравнивает запрошенное количество с остатком
5. Система отражает выбранную позицию в заказе

**Альтернативные потоки:**
- Если количество одного из необходимых товаров недостаточно — система отображает модальное окно с уведомлением «Заменить позицию?» (продолжение с шага 5)

**Исключения:**
- Если клиент не соглашается на замену — менеджер должен иметь возможность отменить заказ 

**Постусловия:** Товары успешно добавлены к заказу, либо заказ отменён, если клиент не согласился на замену

---

## UC-03. Предложить замену товара

- **Актёр:** Менеджер
- **Цель:** Предложить клиенту замену недостающей позиции и зафиксировать его решение
- **Предусловия:** По одной из позиций заказа остатка недостаточно

**Основной поток:**
1. Система показывает менеджеру позицию, по которой недостаточно остатка
2. Менеджер открывает каталог товаров для подбора замены
3. Менеджер выбирает товар-замену и предлагает его клиенту (по телефону/переписке)
4. Менеджер фиксирует в системе решение клиента — согласие на замену
5. Система заменяет исходную позицию на выбранный товар-замену с указанным количеством
6. Система повторно проверяет наличие по новой позиции (переход к UC-02, шаг 4)

**Альтернативные потоки:**
- Если клиент не согласен ни на одну из предложенных замен — менеджер фиксирует отказ вместо согласия (переход к исключению)

**Исключения:**
- При отказе клиента от замены менеджеру становится доступна отмена заказа. Если менеджер не отменяет заказ сразу, позиция остаётся помеченной как «недостаточно» до отдельного решения
- Если в каталоге нет подходящей по типу замены (например, для узкоспециализированного товара) — менеджер не может предложить замену через систему и решает вопрос вне неё (созвон с поставщиком), сценарий прерывается без изменения статуса позиции

**Постусловия:** Позиция обновлена на товар-замену и наличие подтверждено (успешный путь), либо клиент отказался от замены — заказ ожидает решения менеджера (продолжение или отмена)

## UC-04. Создать клиента

- **Актёр:** Менеджер
- **Цель:** Создать нового клиента в системе, не допустив дублирования
- **Предусловия:** Менеджер авторизован в системе

**Основной поток:**
1. Менеджер открывает форму создания клиента
2. Менеджер вводит фамилию, имя и телефон клиента
3. Менеджер сохраняет форму
4. Система проверяет, есть ли клиент с таким номером телефона
5. Система создаёт нового клиента, привязывая его к текущему менеджеру как ответственному
6. Система отображает карточку созданного клиента

**Альтернативные потоки:**
- Если клиент с таким телефоном уже существует — система не создаёт дубликат, а показывает менеджеру карточку существующего клиента с именем ответственного менеджера (продолжение с шага 6)
- Менеджер может открыть показанную карточку существующего клиента вместо создания новой

**Исключения:**
- Если обязательные поля (фамилия, имя, телефон) не заполнены — система отклоняет сохранение и подсвечивает незаполненные поля
- Если два менеджера одновременно пытаются создать клиента с одним и тем же телефоном — уникальное ограничение на уровне БД пропускает только первый запрос

**Постусловия:** Клиент создан и привязан к ответственному менеджеру, либо менеджер направлен к уже существующей карточке клиента

## UC-05. Сборка и отправка заказа

- **Актёр:** Кладовщик
- **Цель:** Провести заказ через статусы «В сборке» → «Отправлен»
- **Предусловия:** Заказ находится в статусе «Подтверждён»

**Основной поток:**
1. Кладовщик открывает список заказов, ожидающих сборки
2. Кладовщик выбирает заказ и просматривает позиции
3. Кладовщик нажимает «Собрано»
4. Система переводит заказ в статус «В сборке»
5. Кладовщик передаёт заказ в транспортную компанию физически
6. Кладовщик нажимает «Отправлено»
7. Система переводит заказ в статус «Отправлен»

**Альтернативные потоки:**
- Если пока заказ находился в статусе «В сборке», менеджер его отменил — система показывает кладовщику уведомление об отмене вместо кнопки «Отправлено» (продолжение с шага 7)

**Исключения:**
- Если заказ уже не в статусе «В сборке» — кнопка «Отправлено» недоступна, действие невозможно

**Постусловия:** Заказ последовательно переходит «Подтверждён» → «В сборке» → «Отправлен», либо процесс прерывается отменой заказа

## UC-06. Синхронизация остатков с 1С

- **Актёр:** Планировщик (автоматический, не человек)
- **Цель:** Обновить остатки товаров в системе данными из 1С по расписанию
- **Предусловия:** Настроено расписание синхронизации; доступны учётные данные для подключения к 1С

**Основной поток:**
1. Планировщик инициирует синхронизацию по расписанию
2. Система запрашивает у 1С текущие остатки товаров
3. 1С возвращает список остатков
4. Система обновляет локальные остатки, считая данные 1С основными

**Альтернативные потоки:**
- Отсутствуют 

**Исключения:**
- Если 1С не отвечает или возвращает ошибку — система оставляет текущие остатки без изменений и фиксирует ошибку в логе для последующего разбора

**Постусловия:** Остатки товаров обновлены согласно данным 1С, либо остались без изменений при ошибке синхронизации
