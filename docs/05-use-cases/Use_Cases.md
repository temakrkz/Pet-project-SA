# Use Case — процесс «Оформление заказа»

## UC-01. Отменить заказ

- **Актёр:** Менеджер
- **Цель:** Отменить заказ клиента и зафиксировать причину отмены
- **Предусловия:** Заказ существует в системе и имеет статус, отличный от «Отправлен»

**Основной поток:**
1. Менеджер открывает карточку заказа
2. Система отображает текущий статус заказа и доступные действия
3. Менеджер нажимает «Отменить заказ»
4. Система запрашивает причину отмены
5. Менеджер указывает причину
6. Система меняет статус заказа на «Отменён»
7. Система сохраняет причину отмены в истории заказа

**Альтернативные потоки:**
- 3a. Если заказ имеет статус «В сборке» — после шага 6 система дополнительно уведомляет кладовщика об отмене (продолжение с шага 7)

**Исключения:**
- 3b. Если заказ уже имеет статус «Отправлен» — кнопка «Отменить» недоступна, сценарий не может быть начат

**Постусловия:** Заказ имеет статус «Отменён», причина отмены сохранена, при необходимости кладовщик уведомлён

**Связанные требования:** US-03, Т4

## UC-02. Добавить товары к заказу (проверка наличия)

- **Актёр:** Менеджер
- **Цель:** Добавить товары к заказу
- **Предусловия:** Заказ создан в системе, позиции ещё не добавлены

**Основной поток:**
1. Менеджер открывает систему с остатками на складе
2. Система отражает название, цену и остаток по каждому товару
3. Менеджер добавляет товар к заказу с указанием нужного количества
4. Система сравнивает запрошенное количество с остатком
5. Система отражает выбранную позицию в заказе

**Альтернативные потоки:**
- 4a. Если количество одного из необходимых товаров недостаточно — система отражает модальное окно с уведомлением «Заменить позицию?» (см. UC-03)

**Исключения:**
- Если клиент не соглашается на замену — менеджер должен иметь возможность отменить заказ (см. UC-01)

**Постусловия:**
- Товары успешно добавлены к заказу, либо
- Заказ отменяется, если клиент не согласился на замену

**Связанные требования:** US-02, US-04

---

## UC-03. Предложить замену товара (эскиз — не детализирован до уровня UC-01/UC-02)

- **Актёр:** Менеджер
- **Цель:** Предложить клиенту замену недостающей позиции и зафиксировать его решение
- **Предусловия:** По одной из позиций заказа остатка недостаточно (см. UC-02, альтернативный поток 4a)
- **Основной поток (кратко):** менеджер выбирает товар-замену из каталога → фиксирует согласие/отказ клиента → при согласии позиция обновляется и наличие проверяется повторно (переход к UC-02) → при отказе доступна отмена (UC-01)
- **Связанные требования:** US-04
