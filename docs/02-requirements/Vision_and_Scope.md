## 1. Видение (Vision)

**Проблема:** заказы теряются и дублируются из-за разрозненных Excel-файлов у каждого менеджера, отсутствия единой базы клиентов и неактуального учёта остатков на складе.

**Цель проекта (в формулировке заказчика):** *«Хочу, чтобы всё было в одном месте, чтобы новый менеджер мог разобраться за пару дней, а не полгода, и чтобы я как руководитель мог посмотреть в моменте, сколько заказов сейчас в работе, сколько зависло и сколько денег в них заморожено».*

**Метрика успеха:** сокращение случаев потери/дублирования заказов; сокращение времени адаптации нового менеджера; появление у руководителя оперативной сводки по заказам.

## 2. Источник требований (трассировка к pain points)

| Требование | Из какой проблемы выросло (см. AS-IS, раздел 5) |
|---|---|
| Единая база заказов | Разрозненные Excel-файлы у каждого менеджера, ручная сверка отчётов |
| Единая база клиентов с привязкой к менеджеру | Один клиент обслуживается разными менеджерами параллельно |
| Учёт остатков на складе | Тетрадь кладовщика не синхронизирована с реальностью |
| Статусы заказов, видимые всем участникам | Нет фиксированных статусов, невозможно отследить этап заказа |

## 3. Список требований (сырой, до приоритизации)

| № | Требование (как сформулировал заказчик) | Комментарий аналитика |
|---|---|---|
| Т1 | Единая база заказов | — |
| Т2 | Единая база клиентов с активными заказами и ответственным менеджером | — |
| Т3 | Учёт товаров на складе | Штрихкодов и артикулов сейчас нет вообще, поставщики не маркируют товар. Часть товара считается мешками/паллетами, часть — поштучно/в погонных метрах. Решение "1С + сканирование ШК" от заказчика не подходит в исходном виде — нужен отдельный вариант идентификации (например, условные позиции по названию + единица измерения, без физического сканирования) |
| Т4 | Статусы заказов для всех участников (менеджер, кладовщик, руководитель) | — |
| Т5 | Дашборд для руководителя (кол-во заказов в работе, зависшие, сумма "замороженных" денег) | Уточнено: "замороженные деньги" = сумма принятых, но ещё не доставленных и не оплаченных заказов |

## 4. Ограничения проекта

| Тип ограничения | Значение |
|---|---|
| Бюджет | Порядок — несколько сотен тысяч рублей на первую версию (точная сумма гибкая, зависит от предложенного объёма) |
| Сроки | Ожидание рабочего результата через 2-3 месяца |
| Кадры | Найм новых людей не планируется, обучение текущих сотрудников — да |
| Технические ограничения пользователей | Кладовщик (55 лет) не технически подкован — нужен интерфейс с крупными элементами, минимумом текстового ввода, без сложных меню; заказчик предложил рассмотреть голосовой ввод |
| Существующие системы | 1С используется для бухгалтерии, но остатки туда не заносятся |

## 6. Что нужно уточнить дополнительно

- Насколько реалистичен голосовой ввод для кладовщика (заказчик предложил идею сам, но не оценивал техническую и практическую сторону) — уточнить на следующей встрече
- Точная схема учёта товара без ШК: по каким единицам вести остатки для россыпных/паллетных позиций, чтобы предложить решение для Т3 на этапе to-be
